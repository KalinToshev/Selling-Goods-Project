# SellingGoods

Конзолно Java приложение за **симулация на продажба на стоки** в магазин при **конкурентен достъп**: множество купувачи пазаруват едновременно, извършват „checkout“, генерират **касови бележки (receipts)**, а магазинът поддържа и отпечатва **крайните наличности**.

## Основни функционалности

- Дефиниране на продукти (`Product`) и артикули в количка (`CartItem`)
- Стартиране на множество купувачи като конкурентни задачи (`BuyerTaskCallable`)
- Изпълнение на задачите чрез `ExecutorService` (фиксиран thread pool)
- „Checkout“ в магазин (`Store`) и генериране на бележка (`Receipt`) с редове (`ReceiptLine`)
  - показва **заявено** срещу **реално продадено** количество (ако наличността не стига)
- Визуализация в конзолата:
  - логове за старт/край на купувачите и нишката (thread)
  - списък от генерирани receipts
  - крайни наличности в магазина

## Технологии

- Java (конзолно приложение)
- Gradle (wrapper)
- Lombok
- Java Concurrency (`ExecutorService`, `Callable`, `Future`)
- JUnit 5 (настройки за тестове)

## Изисквания

- Инсталиран JDK (препоръчително 17+)
- Няма нужда от Docker/база данни
- (По желание) IntelliJ IDEA за най-лесно стартиране
  - важно: включен **Annotation Processing** за Lombok

## Стартиране на приложението

1) Отвори проекта.
2) Увери се, че Lombok работи (Annotation Processing е включен).
3) Стартирай main класа:
   - `src/main/java/Main.java`

## Конфигурация

- Броят нишки в thread pool-а се задава в:
  - `src/main/java/config/ExecutorServiceConfig.java` (по подразбиране: `newFixedThreadPool(4)`)

- Сценарият на симулацията (брой купувачи, избор на продукти и количества) е в:
  - `src/main/java/Main.java`

## Структура на проекта

- `config/` — конфигурация на executor service
- `model/` — домейн модели: `Product`, `CartItem`, `Receipt`, `ReceiptLine`
- `store/` — логика за магазин и наличности (`Store`)
- `tasks/` — конкурентни задачи за купувачи (`BuyerTaskCallable`)
